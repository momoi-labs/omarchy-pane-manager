Pane Manager — panel with tabs and grouped sections

All decided. Group = left rail, no accent. Tabs = underline, three of them, Reset included. Apply to sits above the tab strip and governs the panel. Tab and section no longer repeat each other: a tab with one section has no group header — option A in section 2. The panel below is the target; section 3 is what gets built.

2. Tab vs. section — three ways out

The duplication is real: a tab already titles its content, so a single group inside it repeats the word and adds a rail around everything, which groups nothing.

  • A · The tab is the section title. Recommended, drawn above. A tab with one section keeps the rail but drops the label — the strip is the label. The badge and the one-line description stay, as a caption at the top of the railed body. A tab with two or more sections gives each one its own labelled Group instead.
    Gain: nothing is said twice, and the rail still says where the tab's content begins and ends.
  • B · Rename the tabs one level up. Keep every section in a group and make tab names broader than section names — Panes / Looks / Reset, with BORDER and later GAPS as sections inside Looks. No duplication because the words differ by design.
    Cost: today Looks has exactly one section, so the rail is decoration until a second one exists.
  • C · Drop the tabs for now. One scrolling column of rail groups, tabs introduced when there are enough sections to need them (4+).
    Cost: the panel keeps growing downward, which is what started this.

3. What I'd build

  • Group.qml — 2px rail, label, optional right-aligned badge, optional description, content as the default property; the label is optional, so a one-section tab uses the same component headerless. No accent state.
  • Tabs.qml — underline strip plus optional caption / badge line, one Tab stop, h/l and ←/→ to move, Enter/Space to activate: the same keyboard grammar as Segmented.qml. The strip holds the current tab in a property on the panel root, so it outlives an open/close cycle but not a shell reload. caption and badge are optional and left empty on Panes.
  • ScopedSetting.qml — stops being a BorderSurface and becomes a Group: the box around each setting goes away, the rail carries it instead. Same properties, same signal.
  • PaneManager.qml — Apply to becomes a Group above the strip; the three scoped rows, the border controls and the two resets move into tabs; both PanelSectionHeaders, all four PanelSeparators (including the duplicated pair at lines 512–514) come out.

4. Decisions

  • Option A for the tab/section overlap: a tab with one section keeps the rail and drops the label. So Border and Reset have no group title — only their caption.
  • Caption only where it adds something. Panes has none: three titled rows already say what the tab is. Border and Reset keep theirs, because "every workspace" and "this also undoes the scrolling layout" are not readable off the tab name.
  • Cards become rails. ScopedSetting loses its BorderSurface; the rail carries the row.
  • Disabled dims the whole group, rail included, at the shell's 0.45.
  • Reset keeps its own tab — it is the way out of a mangled layout, so it stays one keystroke away.
  • Last tab is remembered in memory, not on disk: the panel reopens where you left it and falls back to Panes after a shell reload.
  • No accent rail — the per-row badges already say which values differ from global.
Colours, radii and the 1px seam are sampled from the running panel; the real components read them from Style / Color so themes keep working.
